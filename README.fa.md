# CodePoint

> 🌍 [English version](./README.md)

مدیریت قطعه‌کد فارسی با رابط کاملاً راست‌به‌چپ — کدها را ذخیره کن، جستجو کن، بر اساس زبان مرور کن، با شماره خط و هایلایت سینتکس بخوان و از منوی راست‌کلیک اختصاصی ویرایش یا حذفشان کن. پوسته روشن و تیره، PHP و MySQL خام روی آپاچی، بدون فریم‌ورک و بدون مرحله build.

## ✨ امکانات

### 📚 کتابخانه کدها

- لیست کارتی که برای هر قطعه‌کد عنوان، برچسب زبان، توضیح محدودشده به دو خط و متا (شناسه، تعداد کاراکتر، تعداد خط) را نشان می‌دهد.
- پنل حالت خالی وقتی جستجو یا فیلتر هیچ نتیجه‌ای ندارد.
- متای حجم به‌صورت نسبی (بایت / کیلوبایت) با رندر امن LTR، طوری که `80 B` در سند راست‌به‌چپ هرگز به `B 80` وارونه نشود.

### 🔍 جستجو و فیلتر

- جستجو در سه حالت: بر اساس **عنوان**، بر اساس **زبان**، یا بر اساس **شناسه** — که با کنترل سه‌بخشی در سایدبار انتخاب می‌شود.
- لیست فیلتر زبان که از کوئری `GROUP BY` ساخته می‌شود و کنار هر زبان تعداد قطعه‌کدهایش را نشان می‌دهد.
- جستجوی فعال هنگام کلیک روی فیلتر زبان حفظ می‌شود، پس فیلترها همدیگر را ریست نمی‌کنند بلکه ترکیب می‌شوند.

### 💬 نمایشگر کد

- صفحه اختصاصی `read.php?code_id=N` با نوار ابزار چسبان: عنوان قطعه‌کد، لیست انتخاب زبان، دکمه‌های **کپی** و **کپی با شماره خط**.
- ستون شماره خط که با کد هایلایت‌شده هم‌تراز می‌ماند، و ناحیه اسکرول افقی برای خطوط بلند.
- هایلایت سینتکس با highlight.js 11.11.2، که با تغییر زبان دوباره اعمال می‌شود. ادیتور در هر دو پوسته تم‌های سینتکس خودِ گیت‌هاب را می‌پوشد — `github` برای روشن و `github-dark` برای تیره — و `tools/style.css` نوار ابزار، ستون شماره خط و مرزها را با همان پالت‌ها هماهنگ کرده تا نمایشگر از صفحه جدا دیده شود.
- سایدبار شامل متای قطعه‌کد و توضیح کامل آن.

### 🖱️ منوی راست‌کلیک

- راست‌کلیک روی هر کارت کد، یک منوی اختصاصی با **کپی**، **ویرایش** و **حذف** باز می‌کند و منوی پیش‌فرض مرورگر را کنار می‌زند.
- یک دکمه **«⋯»** روی هر کارت همان منو را باز می‌کند، تا دستگاه‌های لمسی که راست‌کلیک ندارند هم هر سه عمل را داشته باشند.
- کامل با کیبورد: `↑`/`↓` برای حرکت بین آیتم‌ها (با چرخش از آخر به اول)، `Home`/`End` برای پرش به ابتدا/انتها، و `Esc` برای بستن. بستن، فوکوس را به دکمه‌ای که منو را باز کرده بود برمی‌گرداند.
- منو داخل کادر دید صفحه کلمپ می‌شود و با `Esc`، کلیک بیرون، اسکرول یا تغییر اندازه پنجره بسته می‌شود.
- ویرایش از همان مودال «ثبت کد جدید» در حالت ویرایش استفاده می‌کند و متن دکمه‌ها به **ویرایش کد** / **ذخیره تغییرات** تغییر می‌کند.
- حذف بعد از گرفتن تأیید انجام می‌شود و همیشه به `index.php` برمی‌گردد.
- صفحه نمایشگر همین دو عمل را به‌صورت دکمه‌های ساده **ویرایش** و **حذف** دارد، پس بدون برگشتن به لیست هم می‌شود ویرایش کرد.

### 💾 پشتیبان JSON

- دکمه‌ی **خروجی JSON** در نوار بالا، همه‌ی قطعه‌کدها را در یک فایل دانلود می‌کند: `{ format, version, exported, count, snippets: [...] }` که `code_id` در هر ردیف نگه داشته می‌شود تا فایل بشود دوباره ادغام شود، نه اینکه کورکورانه اضافه شود.
- دکمه‌ی **ورود JSON** فایلی انتخاب می‌کند، تأیید می‌گیرد، و نتیجه را در یک توست گزارش می‌دهد: چند تا اضافه شد، چند تا به‌روزرسانی شد، چند ردیف رد شد.
- ورود بر اساس `code_id` **ادغام** می‌کند — شناسه‌ای که از قبل هست به‌روزرسانی می‌شود، شناسه‌ی جدید درج می‌شود. **هیچ‌چیز هرگز پاک نمی‌شود**، پس وارد کردن یک بکاپ قدیمی نمی‌تواند کدهای جدیدتر را از بین ببرد.
- اگر یکی از چهار فیلد یک ردیف خالی یا نامعتبر باشد، آن ردیف رد می‌شود و شمارشش در توست می‌آید، پس import ناقص هیچ‌وقت بی‌صدا نمی‌ماند.
- کل دسته در یک تراکنش اجرا می‌شود، پس خطای نیمه‌راه دیتابیس را برمی‌گرداند و جدول نیمه‌کاره رها نمی‌کند.
- خروجی یک `GET` است (فقط می‌خواند)؛ ورودی یک `POST` است و از طریق فایل‌پیکر انجام می‌شود.

### ⚙️ رابط کاربری

- چیدمان کاملاً راست‌به‌چپ ساخته‌شده با **ویژگی‌های منطقی** CSS (`margin-inline-*`، `padding-inline`، `border-inline-*`) به‌جای left/right ثابت.
- دیزاین‌سیستم دست‌نویس در یک فایل استایل واحد — متغیرهای CSS برای رنگ، فاصله، شعاع و سایه، به‌همراه قرارداد کلاس‌ها مستندشده در هدر فایل.
- **حالت تیره** با دکمه‌ای در نوار بالا: تا وقتی خودت انتخاب نکنی از تنظیم سیستم‌عامل پیروی می‌کند، و بعد از انتخاب، همان انتخاب بین ری‌لودها باقی می‌ماند. کل پالت یک بلوک `light-dark()` است که `color-scheme` آن را جابه‌جا می‌کند، پس فایل استایل دومی برای هماهنگ نگه‌داشتن وجود ندارد.
- دکمه هم آیکون خورشید دارد هم ماه، و CSS خودش یکی را نشان می‌دهد؛ یعنی از اولین رنگ‌آمیزی درست است. پوسته ذخیره‌شده را یک اسکریپت مسدودکننده در `<head>` اعمال می‌کند، پس فلاش پوسته اشتباه اصلاً ممکن نیست.
- نمایشگر کد در هر دو پوسته ظاهر ادیتور خودش را نگه می‌دارد (روشن و تیره، هر دو با تم گیت‌هاب) و در حالت تیره یک border می‌گیرد تا از صفحه جدا بماند.
- فرم «ثبت کد جدید» داخل یک مودال بومی `<dialog>` قرار دارد تا سایدبار فضای اسکرول خودش را حفظ کند.
- واکنش‌گرا: چیدمان دو ستونی در دسکتاپ، تک‌ستونی در `1024px`، و wrap شدن نوار ابزار و کوچک شدن فونت کد در `640px`. زیر `640px` چهار عمل نوار بالا به سطر خودشان می‌روند تا صفحه را کنار نزنند.
- فونت وزیرمتن برای رابط فارسی، با بازگشت به `system-ui` / `Tahoma`.

### 🔒 ایمنی

- هر مقدار پیش از رسیدن به کوئری با `SQLHelper::escape()` (`mysqli_real_escape_string`) escape می‌شود — هیچ الحاق رشته‌ای داخل SQL انجام نمی‌شود.
- همه مقادیر نمایش‌داده‌شده از `htmlspecialchars()` عبور می‌کنند.
- `code_id` به `(int)` تبدیل می‌شود، پس هرگز نمی‌تواند SQL حمل کند.
- `SQLHelper` فراخوانی‌های اتصال و کوئری را در `try/catch` برای `mysqli_sql_exception` پیچیده — چیزی که PHP 8.1+ به‌صورت پیش‌فرض پرتاب می‌کند.
- حذف از طریق یک فرم مخفی با متد **POST** انجام می‌شود، نه GET، پس هیچ لینک خزیده‌شده یا prefetchشده‌ای نمی‌تواند کدی را پاک کند.
- مقصد ریدایرکت در `return_to` به `index|read` محدود شده است، پس نمی‌تواند به یک ریدایرکت باز تبدیل شود.
- **ورودی هیچ‌وقت پاک نمی‌کند.** بر اساس `code_id` ادغام می‌کند، پس برگرداندن یک بکاپ قدیمی ردیف‌های موجود در فایل را به‌روزرسانی و بقیه را درج می‌کند، و نمی‌تواند کدی که از فایل جدیدتر است را حذف کند.
- فایل ورودی ورودی نامعتبر است، پس به‌جای مسیر escape-و-الحاق بقیه‌ی اکشن‌ها، از **prepared statement با پارامترهای bind‌شده** عبور می‌کند و هر فیلد پیش از رسیدن به کوئری از نظر نوع و خالی‌نبودن بررسی می‌شود.
- کل import در یک تراکنش اجرا می‌شود و با هر خطا برمی‌گردد، پس یک ردیف خراب در میانه‌ی یک فایل بزرگ نمی‌تواند جدول را نیمه‌کاره رها کند.
- متن کدی که به منو داده می‌شود داخل یک `data-` attribute سفر می‌کند که هر کاراکترش escape و خطوط جدیدش پیش از entity شدن به `LF` نرمال می‌شود — چون پارسر HTML یک `CR` خام داخل attribute را بازنویسی می‌کند و در غیر این صورت هر `CRLF` به یک خط خالی تبدیل می‌شد.

## 📁 ساختار پروژه

```text
CodePoint/
├── index.php               # خانه: جستجو، فیلتر زبان، لیست کارت کدها، منوی راست‌کلیک
├── read.php                # نمایشگر: شماره خط، هایلایت، دکمه‌های کپی + ویرایش/حذف
├── api.php                 # endpoint پست: درج / ویرایش / حذف / ورود JSON
├── backup.php              # endpoint گت: خروجی گرفتن از همه کدها به‌صورت دانلود JSON
├── database.sql            # اسکیما: CREATE DATABASE + CREATE TABLE codes (+ داده نمونه اختیاری)
├── screenshot/
│   └── screenshot.png      # اسکرین‌شات استفاده‌شده در این README
└── tools/
    ├── SQLHelper.php       # لایه دیتابیس: escape()، fetchAll()، fetchOne()، sendQuery()
    ├── header.php          # پارشال مشترک: <head>، اسکریپت بدون فلش تم، نوار بالا، مودال‌ها، توست
    ├── import.php          # اکشن import: اعتبارسنجی JSON آپلودشده و ادغام بر اساس code_id
    └── style.css           # دیزاین‌سیستم (توکن‌ها، جفت‌های light-dark()، چیدمان، کامپوننت‌ها)
```

- **`index.php`** — نقطه ورود. عبارت جستجو و زبان فعال را می‌خواند، شرط `WHERE` را با مقادیر escape‌شده می‌سازد و لیست کارت‌ها به‌همراه سایدبار فیلتر را رندر می‌کند. منوی راست‌کلیک هم مال همین فایل است: یک شنونده `contextmenu` و یک شنونده `click` دلیگیت‌شده و یک هندلر کیبورد، پس برای همه‌ی کارت‌ها فقط یک شنونده per event کافی است.
- **`read.php`** — نمایشگر کد. روی `(int)$_GET['code_id']` یک `fetchOne()` می‌زند و سپس نوار ابزار، ستون شماره خط و بدنه هایلایت‌شده را می‌سازد. اگر قطعه‌کد نبود، به‌جای رندر صفحه‌ی خراب به `index.php` ریدایرکت می‌شود.
- **`api.php`** — مقصد فرم برای هر نوشتن. `action` یکی از `insert`، `update`، `delete` یا `import` را انتخاب می‌کند؛ درج و ویرایش اعتبارسنجی مشترک (خالی نبودن عنوان، زبان، توضیح و کد) و همان چهار مقدار escape‌شده را دارند. حذف فقط یک شناسه‌ی `(int)` می‌گیرد. اکشن `import` کارش را به `tools/import.php` می‌سپارد.
- **`backup.php`** — خروجی گرفتن. همه‌ی ردیف‌ها را می‌خواند، در یک پاکت نسخه‌دار می‌پیچد و با `Content-Disposition: attachment` به‌صورت دانلود می‌فرستد. `GET` بودنش اینجا درست است چون فقط می‌خواند.
- **`tools/import.php`** — توسط `api.php` برای اکشن `import` include می‌شود. برخلاف بقیه‌ی اکشن‌ها از prepared statement استفاده می‌کند (نه مسیر escape-و-الحاق)، چون داده از یک فایل نامعتبر می‌آید. پاکت را اعتبارسنجی می‌کند و بعد هر ردیف را در یک تراکنش، بر اساس `code_id` ادغام می‌کند.
- **`tools/header.php`** — توسط هر دو صفحه include می‌شود. قبل از include کردن، `$pageTitle` و `$activePage` را تنظیم کنید. مودال مشترک، فرم مخفی حذف، فرم مخفی ورودی، پشته‌ی توست و `window.codePoint` (`openEditor`، `remove`، `copy`، `toast`، `clipboard`) هم در همین‌جا هستند، پس هر دو صفحه از یک ویرایشگر مشترک استفاده می‌کنند.
- **`tools/style.css`** — کل پالت در یک بلوک `:root` به شکل جفت‌های `light-dark()` است، پس یک کلید `color-scheme` تعیین می‌کند از کدام سمت هر جفت استفاده شود. **توکن‌های `--viewer-*` به دو تم highlight.js قفل شده‌اند** (`github` و `github-dark`)؛ عوض کردن یکی بدون آن یکی جفت‌وجور نیست.
- **`tools/SQLHelper.php`** — اطلاعات اتصال و همه متدهای کوئری را نگه می‌دارد. **اول این فایل را برای تنظیم اتصال ویرایش کنید.**

## 🚀 اجرا و بیلد

چیزی برای بیلد کردن وجود ندارد — نه Composer، نه باندلر. پوشه را در وب‌روت کپی کنید و یک جدول بسازید.

### ۱. انتقال پروژه

پوشه `CodePoint/` را داخل `htdocs` در XAMPP کپی کنید:

```bash
# ویندوز
xcopy /E /I CodePoint "C:\xampp\htdocs\CodePoint"
```

> 💡 اگر پوشه را داخل یک پوشه به نام `www` نگه می‌دارید، آدرس را در گام بعد اصلاح کنید — آدرس وب‌سایت از مسیر **زیر داکیومنت‌روت** می‌آید، نه از چیدمان دیسک شما.

### ۲. ساخت پایگاه داده

اسکیما در [`database.sql`](./database.sql) آمده، پس می‌توانید همان را ایمپورت کنید. از خط فرمان:

```bash
mysql -u root -p < database.sql
```

یا در phpMyAdmin (`http://localhost/phpmyadmin`): **Import → انتخاب `database.sql` → Go**. فایل UTF-8 است، پس عنوان‌های فارسی درست ایمپورت می‌شوند.

این فایل دیتابیس `code_point`، جدول `codes` و یک ایندکس روی `code_lang` برای فیلتر زبان می‌سازد:

```sql
CREATE DATABASE IF NOT EXISTS `code_point`
    DEFAULT CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE `code_point`;

DROP TABLE IF EXISTS `codes`;

CREATE TABLE `codes` (
    `code_id`         INT AUTO_INCREMENT PRIMARY KEY,
    `code_title`      VARCHAR(255) NOT NULL,
    `code_text`       TEXT         NOT NULL,
    `code_lang`       VARCHAR(100) NOT NULL,
    `code_description` TEXT        NOT NULL,

    -- the language filter lists every code_lang with its count
    INDEX `idx_codes_lang` (`code_lang`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

> ⚠️ فایل `database.sql` شامل `DROP TABLE IF EXISTS codes` است — یعنی ایمپورت آن روی یک نصب موجود **کدهای شما را پاک می‌کند**. همچنین بلافاصله بعد از `CREATE TABLE` سه قطعه‌کد نمونه به‌صورت کامنت‌شده دارد؛ اگر داده نمونه می‌خواهید، آن بلوک را از حالت کامنت خارج کنید.

### ۳. اتصال اپ به دیتابیس

اطلاعات اتصال را در بالای `tools/SQLHelper.php` ویرایش کنید:

```php
private $hostname = "localhost";
private $username = "root";
private $password = "";
private $database_name = "code_point";
```

### ۴. اجرای سرویس‌ها و باز کردن اپ

**Apache** و **MySQL** را از پنل کنترل XAMPP روشن کنید و سپس این آدرس را باز کنید:

```text
http://localhost/CodePoint/
```

> 🌐 فونت Vazirmatn و highlight.js از CDN بارگذاری می‌شوند، پس اولین رنگ‌آمیزی به اینترنت نیاز دارد. چیدمان، ذخیره‌سازی و کپی همگی بدون اینترنت کار می‌کنند.

## 📋 پیش‌نیازها

- **آپاچی** با داکیومنت‌روتی که به پوشه شامل `CodePoint/` اشاره می‌کند.
